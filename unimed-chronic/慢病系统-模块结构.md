## 三、医生视角：患者档案 Tab 绑定决策

### 3.1 医生 5 个核心工作流

医生 80% 的操作都是"以患者为中心"的全景查看，业务与档案绑定有天然合理性。

| 场景 | 医生在做什么 | 患者档案需要显示什么 |
|------|------------|------------------|
| 1️⃣ 日常接诊 | 30 秒内了解患者全貌 | 总览 + 诊疗 + 指标 + 用药 |
| 2️⃣ 随访前查档 | 准备随访问题、看变化 | 上次随访 + 指标趋势 + 用药依从 |
| 3️⃣ 方案调整 | 评估当前方案效果 | 风险评估 + 方案执行 + 近期指标 |
| 4️⃣ 预警处置 | 异常时快速判断原因 | 预警详情 + 近期指标 + 用药 |
| 5️⃣ 转诊/出院 | 整合资料上下游传递 | 完整诊疗 + 检验 + 用药 + 报告 |

### 3.2 🟢 强绑定 Tab（医生看诊必备，14 个）

> **判定标准**：医生看诊时必看，且数据天然属于"某个患者"

| # | Tab | 后端 Controller | 医生为什么需要绑定 |
|:--:|------|----------------|-----------------|
| 1 | 总览 | PatientProfileController | 一屏概览，30 秒掌握 |
| 2 | 时间线 | PatientProfileController（timeline） | 所有事件按时序串联，临床思维线 |
| 3 | 病种管理 | DiseaseRelationController | 主病+并发症关系 |
| 4 | 诊疗记录 | EncounterController | 主诉/诊断/处方历史 |
| 5 | 健康指标 | HealthMetricController | 血压/血糖/体重趋势图 |
| 6 | 检验检查 | OpenapiLisController + OpenapiPacsController | 化验单、影像 |
| 7 | 体检报告 | HealthExamController | 年度体检 |
| 8 | 用药记录 | MedicationController | 当前用药+历史+依从性 |
| 9 | 生活方式 | LifestyleController | 饮食/运动/睡眠打卡 |
| 10 | 风险评估 | RiskAssessmentController | 风险等级、评估明细 |
| 11 | 管理方案 | ManagePlanController | 当前方案执行进度 |
| 12 | 随访记录 | FollowupTaskController | 随访历史、问卷回复 |
| 13 | 预警事件 | WarningController | 该患者的预警历史 |
| 14 | 健康报告 | ReportController | 既往生成的 PDF 报告 |

### 3.3 🟡 半绑定（档案中放摘要卡片/入口按钮，7 个）

> **判定标准**：流程类业务，档案中需要入口或摘要，但完整管理在独立菜单

| # | 业务 | 档案中形态 | 独立菜单中形态 |
|:--:|------|----------|-------------|
| 1 | 签约管理 | 摘要卡片（当前签约+服务包） | 全量列表/履约/续约 |
| 2 | 知情同意 | 已签署列表（只读） | 模板管理+签署管理 |
| 3 | 转诊管理 | 该患者转诊历史 | 全部转诊审批 |
| 4 | 档案共享 | "申请调档"按钮 | 调档审批列表 |
| 5 | 健康教育 | 已推送内容列表 | 内容/规则/推送管理 |
| 6 | OCR 文档 | 已识别附件列表 | OCR 任务/草稿管理 |
| 7 | 患者标签 | 标签展示+快速打标 | 标签字典管理 |

### 3.4 🔴 不绑定档案（纯管理/配置/统计）

> **判定标准**：与单个患者无关，是医生工作台或系统配置

| 类别 | 业务 |
|------|------|
| 医生工作台 | 自定义分组（按医生维度，不是患者维度）|
| 跨患者管理 | 患者结案审批、调档审批、转诊审批、义诊筛查批次 |
| 规则配置 | 评估规则、预警规则、宣教规则、随访问卷模板、报告模板、服务包 |
| 字典配置 | 病种字典、ICD 字典、行政区划、通知模板 |
| 团队管理 | 医生团队、设备管理 |
| 数据分析 | 工作台看板、区域大屏、病种统计 |
| 系统 | 审计日志、运维管理 |

### 3.8 关键工程约束（DRY 原则）

```vue
<!-- 一份组件，两种用法 -->
<EncounterList />                                  <!-- 一级菜单：全局视角 -->
<EncounterList :patient-id="currentPatientId" />   <!-- 患者详情：单患者视角 -->
```

API 统一为 `encounterList(params)`，根据 `patientId` 是否传值自动过滤。

**收益：**
- 一套组件，两种视图（DRY）
- API 一致，避免双倍维护（KISS）
- 数据筛选条件可继承（SOLID-O 开闭原则）
