## 四、设计要点

### 4.1 患者档案瘦身

| 改造前（16 Tab） | 改造后 |
|-----------------|--------|
| 总览 / 时间线 / 标签 / 病种 / 指标 / 用药 / 诊疗 / 检验 / 体检 / 生活 / 风险 / 方案 / 随访 / 签约 / 教育 / 报告 | **14 强绑 Tab**：总览 / 时间线 / 病种 / 诊疗 / 指标 / 检验 / 体检 / 用药 / 生活 / 风险 / 方案 / 随访 / 预警 / 转诊 / 报告 |
| | **7 个半绑卡片**（合并到总览 Tab）：签约摘要 / 标签展示 / 健康教育 / 知情同意 / OCR 文档 / 档案共享 / 转诊入口 |

### 4.2 DRY 组件复用模式

```vue
<!-- 一份组件，两种用法 -->
<EncounterList />                                  <!-- 一级菜单：全局视角 -->
<EncounterList :patient-id="currentPatientId" />   <!-- 患者详情：单患者视角 -->
```

API 统一为 `encounterList(params)`，根据 `patientId` 是否传值自动过滤。

### 4.3 核心设计原则

1. **8 大分组 → 27 一级菜单**：按业务域清晰分组，不再把业务 Tab 全塞在患者档案抽屉里
2. **患者档案瘦身**：16 Tab → 14 强绑 Tab + 7 个半绑摘要卡片
3. **DRY 组件复用**：所有业务列表组件同时支持「全局视图」和「患者视图」（通过 `?patientId=` 参数切换）
4. **抽屉 + 左侧固定信息栏**：患者详情采用宽抽屉，左侧固定患者基本信息 + 快捷操作，右侧 14 Tab 按临床流分组
5. **预警全局可见**：顶部导航栏实时显示预警数量，预警事件作为独立一级菜单
6. **随访日历视图**：随访任务支持日历 + 列表双视图，直观展示每日工作量
